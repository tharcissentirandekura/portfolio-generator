This course treated software as something designed, maintained, revised, and sometimes rebuilt.

- Design continues after the first implementation.
- Maintainability depends on communication.
- Revisiting a decision is responsible engineering.

# My experience

Software from Start to Start Over sharpened my interest in systems that last beyond a demonstration. I thought more deliberately about requirements, changing constraints, collaboration, and the cost of decisions over time.

# What stayed with me

A technically clean implementation can still solve the wrong problem. Feedback and revision are not interruptions to the work; they are how the work becomes useful.

## Advice for someone taking it

1. Document the reason behind a decision, not just the result.
2. Create feedback loops before the project feels finished.
3. Treat changing requirements as information about the problem.
